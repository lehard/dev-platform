## Decisions

- **Declaration in the body.** Parsed from `parse_requirement_body` sections by `requirement_terminal.operator_items(sections)`: list of `{id, action, check}`; a non-matching line, a duplicate id or a missing `Check:` raises naming the line. A Requirement without the section has no items.
- **Decision marker.** `requirement_terminal.ACCEPTANCE_PREFIX = "dev-platform-requirement-acceptance:v1 "`; trust uses the Issue comment's `author_association` in OWNER/MEMBER/COLLABORATOR (the backlog's writers); malformed trusted markers raise. Decisions are read from the Requirement's comments; the body never changes, so the retrospective checkpoint binding is untouched.
- **Gate.** `reconcile_parent` computes open items right after the label/target checks and before the checkpoint and any mutation, raising `OwnerAcceptancePending(RequirementTerminalError)` with the ids. `integration_contour.run_terminal` and the composition terminal path catch exactly that error and return `requirement-awaits-owner-acceptance: <ids>` (a completed outcome), so no attempt is spent and the chain proceeds to cleanup.
- **Accept command.** Owner-gated stage entry (approved ADD): records the marker with the authenticated actor, re-reads decisions, then calls `reconcile_parent(merged_children=<all children>)` only when no item is open; `reconcile_parent` keeps every delivery and checkpoint check, so an incomplete Requirement is reported, not closed.
- **Explicit state.** A helper `issue_state(issue)` returns OPEN or CLOSED and raises otherwise; used by `_await_post_merge` and the closer.
