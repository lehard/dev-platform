## Context

- `delegation_containment.check_containment(before, after)` reports path changes and `head_moved`; `verify_remote_fast_forward` proves ancestry and equality with the local `refs/remotes/origin/<main>` without network; `verify_historical_external_advance` proves a historical `after_head` through the `origin/<main>` reflog inside a time window.
- `delegated_write_guard._classify_containment` applies the verified rule to native-hard Codex runs; `model_routing.recover_external_advance` handles a historical Codex execution flagged as violation.
- `model_routing.postcheck` raises on any violation; `record_claude_execution` therefore leaves the delegation open and records nothing.
- Integration main is fast-forwarded by `finish_task.py` (`merge --ff-only` of the task branch or merged remote main into the integration checkout), `project_sync.py`, and `publication_queue.py` when it reconciles the integration checkout.

## Decisions

1. **Advance receipts.** A helper `record_integration_advance(integration_root, before, after, *, tool, actor_worktree)` appends one JSON line to `<integration>/.claude/integration-advances.jsonl` under an exclusive file lock, after the fast-forward succeeded, with `before`, `after`, `origin_main` (local `refs/remotes/origin/<main>` read at that moment), `actor_worktree` (resolved caller worktree), `tool`, `pid`, `at`. Only advances of the integration checkout's configured main branch are recorded. A write failure fails the calling command explicitly (the fast-forward already happened; the error names the missing receipt so a delegation that overlaps it stays fail-closed rather than silently unclassifiable).
1a. **Receipt attribution.** A writer records a receipt only for its own fast-forward: `project_sync` holds the shared integration lock (`serialized_integration`, as direct finish already does) around its head read, merge and receipt, and both writers prove with `require_own_fast_forward` that the newest entry of main's reflog is their own `merge <source>: Fast-forward` from the head they read. A concurrent move (which turns the merge into an up-to-date no-op with no reflog entry) fails the command without a receipt. A direct finish only records a receipt when main actually moved; a retry after a failed publication finds main already advanced and takes the earlier run's starting head from the reflog entry `merge <task branch>: Fast-forward` to the current head, unless a receipt for that head already exists, so the advance is receipted exactly once.
2. **Shared classifier.** `classify_head_move(integration_root, before, after, *, containment, delegated_worktree, window_start)` in `delegation_containment.py` returns `verified-external-advance` with evidence or `None`. Common facts: no new/changed/disappeared paths; `before` is an ancestor of `after`; `after` equals the local `origin/<main>`. `native-hard` (Codex) needs nothing more (current behavior, `_classify_containment` delegates to it). `detection-only` (Claude) also needs a receipt chain: receipts with `at >= window_start` ordered by time such that the first `before` equals the pre-run head, each `after` equals the next `before`, the last `after` equals the current head, every `after` equals that receipt's `origin_main`, and no `actor_worktree` equals or lies inside the delegated worktree. Unreadable or malformed receipts make classification fail (violation), never skip.
3. **Claude record.** `postcheck` keeps raising for violations except when the classifier verifies the move; then it returns `containment: "clean"` plus `integration_advance` (classification, before, after, receipt list). The raw `head_moved` observation is preserved in that evidence.
4. **Historical recovery (Claude).** `recover-external-advance` accepts a Claude route whose delegation is still open and that has no execution, when the exact friction event belongs to this task, records `head_moved=True` with no path changes, and its time lies after the delegation `opened_at`. The friction event is written by the postcheck that runs only after the native Agent call returned, so integration movement after its time cannot be the delegated child's. Recovery therefore proves the supplied `after_head` with `verify_historical_external_advance` over `[opened_at, recovery time]`, additionally requires that the integration snapshot at recovery time has no new, changed or disappeared paths relative to the route pre-snapshot and that `after_head` equals the current integration head and local `origin/<main>`, and stores a `recovery` record (classification, before, after, friction id) on the open delegation without closing it or creating an execution. The later `record-claude-execution` postcheck starts from the recovered `after_head` and must classify any further movement through receipts (Decision 2). Every refusal writes nothing.
5. **Trust boundary, stated.** Receipts and reflogs are local files a deliberate shell process could forge; the check targets accidental or out-of-scope writes by a detection-only child, consistent with detection-only containment. It never accepts a move without platform-written evidence.

## Risks

- A fast-forward path that misses the receipt keeps blocking Claude records: covered by tests over every site.
- Receipt log growth: append-only small lines; bounded reading by time window.

## Verification

Full platform checks.
