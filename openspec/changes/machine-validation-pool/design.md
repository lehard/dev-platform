## Context

- Heavy validation enters through `select_checks.py --execute` (task archive, finish, lifecycle finalization via `post_review_finalization.trusted_checks_runner`), through `run_test_groups.py` invoked directly, and through `requirement_integration._full_check_commands` for Requirement candidates (which runs `run_test_groups.py --all` in the source repository or project `full_commands` downstream).
- Environments for checks are derived with `credential_free_env` / `project_check_env`, which keep non-credential variables, so a non-secret variable propagates to nested runs; `HOME` may be replaced by a scratch home, so configuration discovery cannot depend on `HOME`.
- A downstream project already proves the lease primitive: an exclusive `flock` held for the run's lifetime and passed to children with `pass_fds`, so the kernel releases it only after every holder exits.
- Agents may run under different OS accounts on the same machine.

## Decisions

1. **Opt-in configuration.** `DEV_PLATFORM_MACHINE_POOL` names a TOML file with exactly these required keys: `directory` (existing directory shared by every participating account), `tokens` (positive int), `wait_timeout_seconds` (positive int), `max_load_per_cpu` (positive float), `min_available_memory_mb` (positive int). Unknown or missing keys, a missing file, a non-directory or an unwritable directory fail explicitly naming the key or path. Unset variable is the declared unpooled mode, printed as `DEV_PLATFORM_MACHINE_POOL: not configured` by every run that would have acquired; it is never inferred from a failure.
2. **Tokens.** `directory/slot-<i>.lock` for `i < tokens`. A lease holds an exclusive non-blocking `flock` on `weight` distinct slot files and writes holder metadata (account, pid, project root, task branch, class, weight, start time) into each held file. A slot is free exactly when its lock is not held; content of a free slot is stale and ignored. Files are created group/other read-write so another account can lock them; a permission error fails naming the file.
3. **Queue and priority.** A waiter creates and exclusively locks `directory/queue/<class-rank>-<time_ns>-<pid>-<nonce>.json`. Only the head ticket (lowest class rank, then oldest; tickets whose lock is not held are dead and are removed after the remover takes their lock) may try to acquire, all-or-nothing: it takes `weight` free slots non-blocking or releases any it took and waits. Ranks: `finalize` 0, `development` 1. The class comes from `DEV_PLATFORM_CHECK_CLASS`; absent means `development` by contract (documented semantics, not a substitute for a required input); any other value fails.
4. **Weight and nesting.** Lease weight is the run's test parallelism (`run_test_groups.resolve_jobs()`), bounded by `tokens`. A granted lease exports `DEV_PLATFORM_MACHINE_POOL_LEASE` (lease id and weight); a nested acquisition that sees it reuses the parent lease and acquires nothing, so finish → select_checks → run_test_groups cannot deadlock on its own tokens. Inside a lease `run_test_groups` uses at most the lease weight as its jobs. Tokens are held by the processes the platform launches with the lease descriptors: the leasing process and the children it starts with `pass_fds`. A process those children start without passing the descriptors (for example a worker a test launches with `subprocess.Popen`) does not hold the tokens, so killing the runner and its test processes while such a descendant still runs frees the tokens and another run may be admitted beside it. This is an accepted limitation decided by the owner and is not mitigated in code. Every platform launch of a pool-aware child (finish and archive selected checks, finalization checks, selected-check commands) passes them together with the exported lease; a pooled lease whose descriptors are not all open, or that does not list exactly one distinct descriptor per token, fails. `run_test_groups` passes the descriptors to its test processes but removes the pool variables from their environment, so tests, and the lifecycle scripts they spawn, never see the developer's pool or the lease.
5. **Load and memory admission.** Before the head acquires, it requires `os.getloadavg()[0] / os.cpu_count() <= max_load_per_cpu` and available memory `>= min_available_memory_mb`; otherwise the run keeps waiting and reports the measured values. Available memory is read without new dependencies: Linux `MemAvailable` from `/proc/meminfo`; macOS `vm_stat` (free + inactive + speculative pages times the reported page size). An unsupported platform or an unparseable measurement fails explicitly naming the source; it is never treated as enough memory.
6. **Bounded wait and visibility.** Waiting prints the holders (project, branch, class, age) and its queue position at start and every 60 s. After `wait_timeout_seconds` the run fails naming the holders; it never runs outside the pool. `python3 scripts/machine_pool.py status` is read-only and prints configuration, holders, waiters and load.
7. **Integration points.** `select_checks.execute` wraps the selected command loop in one lease; `run_test_groups.main` acquires when not nested; `requirement_integration` full-candidate validation wraps its command loop and sets class `finalize`; `post_review_finalization.trusted_checks_runner` sets class `finalize` for its `select_checks` child.

## Risks

- Descendants started without lease descriptors hold no tokens; killing the runner and its test processes can admit another run beside a surviving descendant. The owner accepted this limitation without code mitigation.
- A stale lock cannot occur by construction (kernel-held); a process that hangs keeps its tokens until timeout of the waiters, which then fail visibly naming it.
- Cross-account permissions: documented directory setup; explicit failure otherwise.
- A participant whose environment lacks the variable runs unpooled; it prints `not configured`, so the gap is visible.

## Verification

Unit and multi-process tests in temporary pool directories: configuration validation errors; not-configured line; acquire/release; all-or-nothing under partial availability; priority and FIFO ordering; dead holder (killed child) frees tokens; dead ticket cleanup; timeout failure naming holders; nested reuse without extra tokens; jobs bounded by lease weight; fd inheritance keeps tokens for an orphaned child; status output; integration points acquire exactly once per top-level run. Full platform checks.
