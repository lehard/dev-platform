## Semantic review

- Outcome: `teamai-cli@0.25.0` (npm `latest` at evaluation; the betas were not installed) was piloted in a disposable sandbox. The sandbox isolated HOME, npm prefix/cache and git config, unset tokens, and stubbed the agent CLIs. The pilot covered a copy of the Dev Platform repository and a freshly rendered managed project with Claude and Codex targets. `docs/engineering/upstream-evaluations/teamai.md` records exactly one decision for each of the seven areas: four `reject-for-now` (shared resources and distribution, learnings and recall, codebase wiki, dashboard and analytics) and three `watch-only` (version-bound skills, roles and multi-project, model profiles).
- Spec conformance: no prerelease-only capability is adopted. Each retention names observed compatibility, risk or coupling evidence (for example: mutable default-branch pulls, overwriting of capability-owned skills, `init` applying hooks despite `autoApply: false`, an unreviewed push of learnings, implicit provider calls during codebase extraction, local retention of prompt text); none rests on the existence of our own implementation. The boundary summary keeps every area Dev Platform-owned, and TeamAI is not a dependency. The maintenance-surface baseline was measured at the evaluated revision. The requirement added by this change holds for the outcome in which nothing is adopted.
- Design deviations are recorded truthfully rather than hidden:
  - `teamai init` rejects local repository paths, so the pilot reached the bare repository through a sandbox-only `insteadOf` URL rewrite;
  - rendering the managed project needed `--skip-tasks`, a manual bootstrap and a `git archive` source;
  - Claude and Codex were not launched, so whether Codex reads the rule surfaces remains unknown.
- Safety: the supervisor compared protected HOME files against a baseline taken before the pilot and found them unchanged. `~/.teamai` is absent, no teamai npm package is installed globally, and `~/.claude.json` contains no teamai entries. During cleanup the executor changed the permissions of hardlinked objects in the integration object store and then restored them; the supervisor verified that no loose object is writable and that `git fsck --connectivity-only` is clean. This is recorded as process friction. The sandbox checklist in `docs/engineering/upstream-substitution.md` now requires copying repositories with `--no-hardlinks` or `git archive`.
