Source-bound freshness. `project_evidence.source_bound_fresh` accepts `fresh` and `stale-revision` (revision moved, every bound source identity unchanged); `validate_snapshot` still reports both values. An ADD is fresh when HEAD equals `prepared_against` or when its snapshot evidence is re-proven by `_snapshot_evidence_freshness_errors` and every other evidence source file and every reused-constraint source file (a `#anchor` names a section of that file) still has exactly its blob at `prepared_against` (`git rev-parse <prepared_against>:<path>` equals `git hash-object <path>`; a `#anchor` binds the whole file; an untracked, missing or misspelled source cannot be proven and keeps the ADD stale). These source checks also run when HEAD equals `prepared_against`, so uncommitted edits count (same snapshot/projection digests, unchanged sources); `prepared_against` stays as provenance. The orchestrator's snapshot stage treats a source-bound fresh snapshot with no changed sources as ready. Tests: an unrelated commit keeps the snapshot, the approved ADD and decomposition fresh; a commit to a bound source makes the ADD stale.

Post-handoff independence. `execute_requirement.advance` resolves linked children first, and an unreadable obsolete pre-authoring state no longer stops it before recovery; when pre-authoring is not complete it uses the recorded handoff envelopes only if every envelope digest is carried by exactly one linked child's `requirement-handoff:v1` marker (the child, not the intent-named handoff file, determines the change, so an authored change name different from the intent id is recovered correctly), and only if each ordinary envelope's content digest recomputes to its recorded digest (a direct handoff carrying a stored digest is rejected; its identity is its whole content), every envelope is bound (`source_bindings.intents_digest`) to the current `intents.json`, the recorded set equals that intent set's ready intents, and every dependency resolves inside the set; then it orders them through the existing dependency ordering. Otherwise the existing "not fresh and complete" stop remains. When every mandatory child of a recovered multi-child Requirement is already delivered and the parent is still open, advance now runs terminal reconciliation instead of returning `already-delivered`.
