## Scope reviewed

- **Requirement: Large observations can become cold while exact evidence remains recallable.** `cool_observation` preserves the exact original in `.claude/observations/<change>/<handle>.json` before any hot reference is appended to the route record; the hot reference carries only handle, source/kind metadata, `source_payload`/`hot_payload` size and a bounded excerpt (`_bounded_excerpt`, capped at `OBSERVATION_MAX_EXCERPT_BYTES`). Eligibility is `[observation_lifecycle].min_bytes` (default `OBSERVATION_DEFAULT_MIN_BYTES = 8000`), configurable per project — not a hardcoded paper threshold, per design.md decision 4. Below-threshold and disabled-lifecycle paths return with `handle: None` and touch neither storage nor the route record (`test_small_observation_takes_the_existing_direct_path_without_ceremony`, `test_disabled_lifecycle_also_takes_the_existing_direct_path`). A storage `OSError` fails open to `status: "storage-failed"` with the exact reason, never claiming a successful archive (`test_storage_failure_fails_open_to_the_current_full_observation_path`).
- **Requirement: Cold observations support exact targeted recall.** `recall_observation` requires an explicit `full`, `query`, or `start_byte`/`end_byte` selector — omitting all three raises, so unrelated content is never returned by default (`test_recall_without_explicit_bound_is_rejected`). Byte-range and full recall return the preserved original byte-for-byte; a query match returns bounded surrounding context (`test_exact_recall_returns_the_precise_requested_byte_region`, `test_exact_recall_by_query_returns_bounded_context_around_the_match`, `test_full_recall_escape_hatch_returns_the_entire_preserved_original`). An unknown or stale handle raises `ObservationLifecycleError` explicitly rather than fabricating content (`test_recall_reports_unknown_handle_explicitly_without_fabricating_content`, `test_recall_reports_stale_handle_explicitly_without_fabricating_content`).
- **Requirement: Observation-efficiency evidence remains truthful and bounded.** Evidence reuses the existing `efficiency_unknown_usage`/`efficiency_unknown_measurement` vocabulary rather than a parallel measurement scheme; deterministic `source_payload`/`hot_payload`/`recall_payload` bytes/lines and a deterministic `trigger.intensity` (hot/source byte ratio) are always populated, while `usage` (token/cache fields) stays `{value: null, source: "unknown", status: "unknown"}` for this purely local archive/recall operation, never mislabelled as measured token savings (`test_large_observation_is_cooled_into_bounded_local_storage_with_a_stable_handle` asserts `usage.input_tokens.status == "unknown"`).
- **Non-regression (tasks.md 4.2).** `context_delegations` and the new `observations` field are independently keyed on the `Route` dataclass and parsed independently in `_route_from_payload`; a routing record written before the `observations` field existed still loads with `observations == ()` (`test_route_payload_without_observations_field_defaults_to_empty_tuple`). All pre-existing context-delegation, routing, calibration and managed-lifecycle tests in `tests/test_model_routing.py` pass unchanged alongside the 12 new tests.
