Developer handoff at PR. Review and repair jobs. `pr_review_gate.py` runs Independent Review as a candidate job through the existing reviewer API with the unchanged read-only proof, published through the coordinator's `publish_job`/v2 handoff records (`review-pending`/`reviewing`); material findings route to bounded repair jobs executed through the lifecycle worker harness (validated fast-forward, harness-only expected-head push) or to escalation. Design deviation: jobs call the reviewer API directly rather than its CLI; the same safeguards apply.

Fallback and reuse. Reviewer readiness supports an ordered provider list with requested/executed/reason evidence; an unavailable provider blocks as retryable unless the configuration orders a fallback, never by silent substitution. Gate evidence is bound to task-content identity and reused for unchanged content.
