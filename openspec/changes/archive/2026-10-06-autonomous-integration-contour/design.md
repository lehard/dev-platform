## Context
The current coordinator blocks on overlap and requires the original agent. Friction attribution uses task/branch; Requirement retrospective rejects events attributed to children.

## Decisions
1. Remove overlap blocking; rely on merge result plus actual-candidate checks.
2. Overlap alone never blocks: `_prepare` runs a deterministic `git merge-tree` of current main and the exact head, a clean result continues through GitHub's branch update and checks on the merged head, and only conflicting paths (or a failing required check on the integrated candidate) create an integration-repair job. Integration-repair job via the worker harness (`integration_contour.py`): a disposable checkout merges main, the writer resolves, and only the harness validates (descendant of the claimed head, merged main, edits limited to candidate and conflicted paths, no workflow or evidence files) and pushes with a lease. The record of the pushed head is derivable from the harness's validated-push receipt, so an interrupted run recovers idempotently; an unchanged-identity repair (recovered or advanced) is `ready` with review/finalization evidence reused and the required-checks gate re-run, a changed identity goes to `review-pending`; identity change → review → finalize → ready; max 2 integration-repair attempts then blocked-escalation and dequeue; the coordinator run continues past released candidates (blocked, owned by other work, awaiting finalization or repair) to the next ready one and still reports a block with a non-zero exit when nothing else integrated.
3. Attribution: coordinator events record both candidate task and parent Requirement; Requirement retrospective accepts child-attributed events of its linked children; the retrospective job records checkpoints from recorded events and reports ambiguity rather than inventing `none`.
4. Retrospective, terminal-reconciliation and cleanup are worker jobs derived purely from trusted result receipts of a merged candidate that the coordinator flagged (`attempts["post-merge"] = 1` set when integration starts). `failed`/`blocked` receipts reopen the same obligation as a new attempt up to 3; nothing else is stored. Terminal reconciliation resolves the child and Requirement from the managed branch identity (`agent/br-N-tM-...`) and reconciles the Requirement only when every child is closed; the Requirement checkpoint is recorded by whichever job first sees all children delivered. Cleanup reuses `worktree_cleanup` target removal after proving the local head is contained in the merged PR head. Jobs run on workers with operator credentials and machine-local worktrees; recently merged PRs (one bounded page) are scanned when these kinds are requested.
5. Coordinator friction events are recorded through an explicitly registered sink (`publication_queue.set_friction_sink`; real worker/coordinator entrypoints register the `agent_friction` sink), keyed for idempotence, so library use and tests never write a log.

## Risks and Mitigations
Removing overlap blocking: checks on the actual merged candidate remain mandatory. Automated retrospective could hide judgement: ambiguous or unclassified signals still block.

## Verification
Queue fixtures for overlap, conflict, blocked skip; attribution and retrospective tests; terminal job tests.
