## Context
`dev-platform/checks.toml` declares canonical test groups (parallel/serial) and `run_test_groups.py --verify-coverage` proves they cover exactly the tests. `select_checks.py` selects local-affected or protected-full sets; `full_trigger_patterns` make all platform code full-suite triggers. Archive (`openspec_lifecycle.py`) runs review, then `select_checks.py --base origin/main --execute`. Several test modules install stub or alternate module objects into `sys.modules` at import time.

## Decisions
1. **Substitution hygiene.** All test modules register platform modules through one shared idempotent loader (`tests/_platform_modules.py`) that reuses the instance already registered for the same file, so production code and every test in a process share one module instance; the two existing per-test workarounds are removed. A guard test fails on any direct `sys.modules[...] =` assignment in tests (temporary stand-ins use `mock.patch.dict`), and imports every test module in forward and reverse order in a fresh process, failing when a test namespace holds a platform module beside a different registered instance of the same name.
2. **Affected-test precheck.** A static map (`affected_test_groups.py`) selects, inside each canonical group, the test modules that directly import a changed module or name it in a string (`"x"`, `"x.py"`, `".../x.py"`); a changed test module selects itself. Transitive importers are not followed: lifecycle scripts import each other so densely that the closure selects nearly every group, including the 642-test `fast-b`, which removes the benefit. Unknown, non-Python or control-plane-only paths (selector, checks.toml, workflows) map to nothing and fall straight to full. `run_test_groups.py --changed-file` runs the selection with each group's mode; it never claims coverage. The precheck is opt-in per project through `[settings] affected_precheck` and `affected_source_roots`.
3. **Lifecycle placement.** `select_checks.py --execute` runs the precheck before a full-trigger or unknown-path full selection; archive and finish inherit it without a new command. Its result is written to a separate `affected_precheck` evidence field so the executed-command count that archive verifies is unchanged. A `--no-precheck` escape is not added.
4. **Timing decision.** Per-group wall-clock comes from the runner across comparable runs. Isolation timing of the slowest group (`fast-b`, 496s) located its cost in two modules, so the decision is one structural change to that group: split it into `fast-b`, `fast-e` and `fast-f` balanced by measured module time, and declare the heavy groups (including the existing `fast-c`/`fast-d`, whose contents are unchanged) first because the runner submits groups in declaration order. Coverage verification is identical and the before/after evidence is in `evidence/full-suite-timing.md`. The higher concurrent load exposed a fixed 10s readiness window in `test_pr_reconciliation_concurrency`, whose helper imports the whole `finish_task` chain before signalling; it now uses the shared bounded process deadline (30s, overridable), which still fails a hung helper, consistent with the existing requirement that concurrent tests tolerate normal scheduling.
5. **Helper paths.** A changed non-test module under the test root (for example `tests/_platform_modules.py`) feeds nearly every test module, so it is unmapped and goes straight to the full set rather than doubling the run.

## Risks and Mitigations
A stale import map could miss a test module: the map is generated, its generator is tested, and the full suite still always runs. Sharing one instance could expose state that a test leaks into a module: the full suite runs after conversion and any leak is fixed in the leaking test. Precheck adds time when it passes: it only runs directly affected test modules, typically a fraction of the suite.

## Verification
Isolation and in-group runs for each converted group; guard negative test with a deliberately leaked substitution; precheck unit tests for mapping, unknown paths and abort; real task demonstration with several template script changes; timing evidence with coverage parity.
