## Decisions

- **Declaration.** `delivery` lives in the intent set (owner-approved decomposition, covered by the intents digest). `add_intents.validate_intents` checks `mode == "sequential"` and that `order` lists every intent id once and each is ready.
- **Ordering in advance.** For a sequential Requirement `advance` maps intent ids to authored change names through the handoffs, walks the order, records Done children (with `_done_child_is_delivered`) and materializes and links every child once on the first pass (so the Requirement never reconciles against a partial child set) and runs the existing single-child branch for the first not-Done one only. The shared-candidate and contribution paths are not entered.
- **Rebind trigger.** Only for a sequential Requirement whose pre-authoring status is stale at snapshot, ADD, intents or handoff, with at least one delivered child or a moved main.
- **Attribution.** Changed bound sources are those the stale stage names (snapshot `changed_sources`, ADD file evidence, reused constraints). For each, the first-parent commits on main since the snapshot revision that touch it are listed. A commit is own when its change against its first parent includes `openspec/changes/archive/*-<change>/` of a Done child of this Requirement. Affected sources are the remaining children's bundle capability specs (`openspec/specs/<cap>/spec.md`) plus ADD file evidence and reused constraint sources.
- **Rebind.** The snapshot is rebuilt with `--prior` reusing each projection's existing worker result; the ADD's `prepared_against` and snapshot evidence entries are re-anchored; material fields are compared with the approved document and must be identical; the approval is carried (`approved_by` names the carried digest and the receipt). The intent set and handoffs are re-bound with unchanged content. A receipt `rebind-<n>.json` in the pre-authoring directory records from/to revision, per-source commits with their classification and the old/new digests.
- **Stop.** A foreign commit on an affected source, a changed Requirement digest, a material ADD difference, or an intent/handoff content mismatch raises naming each path with commits or the artifact, and the step to re-approve.
