## Why
Stable Requirement/child identity must appear automatically in normal branch and PR creation so people can understand the work without remembering unrelated GitHub numbers.

## What Changes
- Carry the identity from managed child linkage/provenance into new task branches and PR titles and a standard safe identity block.
- Shared delivery PRs show the parent BR and every included child identity automatically.
- Preserve exact-head publication and resume old task branches without renaming live work.
- Document the public-safe boundary and project-owned taxonomy, using synthetic examples.

## Capabilities
### New Capabilities
None.
### Modified Capabilities
- `managed-work-identity`: automatic branch and publication identity propagation.

## Impact
Managed task start/resume, child and shared PR publication, template upgrades and shared workflow docs. Depends on stable identity intake change.

## Outcome and Evidence
New child branches and PRs clearly expose BR-N/Tn; multi-child shared PR exposes BR-N and all included children; retries repair presentation safely without private references/content. Test project/platform harness compatibility and an actual two-child Requirement delivery, then release and rollout for downstream acceptance.

## Non-goals
Do not rename old live branches, synchronize Issue/PR numbers, publish Requirement prose, or impose product taxonomy.
