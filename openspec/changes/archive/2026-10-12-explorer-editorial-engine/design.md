## Context
The generator is a single stdlib-only script (`scripts/build_explorer.py`) with a fail-closed Markdown renderer, a structure-only `explorer/map.toml`, eight `[[stage]]` entries and source-derived collections. The approved prototype (owner, 2026-10-11, version 4) fixes the information architecture, the texts of three screens and the visual language. Owner decision: stale explanations never block; on `main` history, a blocking variant would have stopped 44 of 163 commits.

## Decisions
1. **Editorial node files.** `explorer/nodes/<id>.toml`, one node per file, parsed with `tomllib`. Strict keys per node kind (`overview`, `stage`, `mechanism`, `part`, `topic`, `term`). Common fields: `id`, `kind`, `title`, `definition`, `sources` (`path#Heading` bindings). Stage and mechanism add `thesis`, `purpose`, `inputs`, `action` (ordered steps), `outputs` (each with consumer and optional target node), `paths` (conditional/error paths with a tag and an outcome), `example` (ordered steps), `children`. Stages add `order` and `transitions` (`to`, `type = main|conditional|return`, `reason`); mechanisms add `used_in` stages and `guarantees`. Text is plain prose with inline code spans only; links are structured fields, never inline Markdown. A node may set `outline = true` and then carries only `kind`, `title`, `definition`, `sources` and structural relations (`order`, `role`, `used_in`, `children`; a stage also `short_title`, `tagline` and `transitions`) so the tree, schema and coverage page stay complete; explanation fields are rejected; it renders as an outline page and is listed as such on the coverage page. The follow-up coverage change removes every outline.
2. **One node, many renderings.** The overview schema, stage pages, mechanism pages, tree, "Внутри · N" cards and the coverage page all read the same node; a card text is the node `definition`. Back-links (`used in`, `comes from`) are derived, not authored twice.
3. **Level 3.** The existing map elements and collections stay as the "Инженерные источники" branch, rendered with the current source-excerpt renderer. Stage ids in `map.toml` stay the same eight ids; stage prose moves to node files; stage `elements` remain the level-3 links.
4. **Validation.** `check`/`build` fail on: unknown keys, missing required fields for the kind, text containing `...`, `…`, unbalanced code spans or Markdown syntax, a sentence not ending in terminal punctuation, a dangling node or stage reference, an unresolvable source binding. These are site-integrity failures, not drift.
5. **Non-blocking drift.** `explorer/editorial-review.json` maps node id to `{binding: digest}` where the digest is SHA-256 of the bound subsection with whitespace runs normalized. `build_explorer.py check` reports bindings whose current digest differs as warnings and exits 0 when that is the only finding; `build_explorer.py mark-reviewed <id>...` rewrites the stamps deterministically. The build renders a marker on stale nodes naming the changed section. The central `scripts/select_checks.py` adapter runs the shared selector unchanged and, under `--execute`, runs `build_explorer.py drift --base <ref>` and prints its warnings; drift never changes the exit code, a failing drift command does. `template/` is not changed. A `[checks.explorer]` entry runs `build_explorer.py check` for changes to bound source surfaces so a renamed bound heading fails locally, not only in CI. In PR CI the build job writes the list to the job summary and a `::warning::` annotation.
6. **Post-merge issue.** A separate `drift-issue` job in `explorer.yml`, on `main` pushes only, with `contents: read` and `issues: write`, runs a repository command (`build_explorer.py drift-issue`) that creates or updates exactly one open issue labeled `explorer-drift` in the same repository with the current stale list, and closes it when the list is empty. Logic lives in the script; the job only orchestrates. Failure of this job never affects build or deploy.
7. **Visual system.** Static HTML and CSS following the prototype tokens; tree as nested lists with the current branch expanded server-side; `assets/explorer.js` only adds expand/collapse-all and keeps the selection in view. The lifecycle schema is inline SVG generated from stage `transitions`; below 980 px a vertical list replaces it. Fonts are system/fallback stacks plus self-hosted files only if licensing allows; no CDN.
8. **Addresses.** `index.html` = overview, `lifecycle/<stage-id>/`, `m/<id>/` for mechanisms and parts, `t/<id>/` for topics and terms, `e/<id>/` unchanged, plus `map/` for the coverage page.

## Risks and Mitigations
- *Second normative source:* node text is explanatory, every node must bind at least one canonical source, and `docs/engineering/explorer.md` states that rules are never authored in nodes.
- *Silent staleness:* warnings locally and in PR, the site marker and the post-merge issue make it visible without blocking.
- *Issue noise:* exactly one issue is updated in place; subsection-level bindings and whitespace normalization limit false positives.
- *Permission creep:* `issues: write` only on the isolated post-merge job; workflow-contract test pins it.
- *Broken links:* stage ids and `e/<id>/` are preserved and a test asserts every previously generated path still exists.

## Ownership and Rollback
Platform-owned, not distributed downstream. Rollback restores the previous templates and map-only loader; node files become unused.

## Open Questions
None. The follow-up child authors the remaining node texts on top of this engine within the same Requirement delivery.
