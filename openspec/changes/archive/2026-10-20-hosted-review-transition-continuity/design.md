## Context

Chain on the runner: `pr_review_gate.complete_review -> offer(repair) -> publication_queue._transition -> emit_friction -> integration_contour.default_friction_sink -> resolve_lineage -> managed_task.authoring_config`. The evidence push precedes the transition, so any failure in this chain leaves a moved head with no record. `candidate_lifecycle` then derives `review-pending` with `gates={}` from the trusted `validated-push` receipt, and the following `reviewing` transition (`inherit_identity=False`, no exact-head record) persists the empty gates.

## Decisions

1. **Attribution by public work identity.** A managed candidate branch already encodes its Requirement's public work identity: `agent/br-N-tM-<change>` is child `BR-N/TM` of `BR-N`, `requirement/BR-N` is the composition. `managed_work_identity.branch_attribution(branch)` returns `{"work_identity": "BR-N", "child_identity": "BR-N/TM" | None}` for a managed branch, `None` for an unmanaged branch, and raises for a branch that looks managed but is malformed. `default_friction_sink` uses only this function: the durable evidence record stores `work_identity`/`child_identity` (no `requirement` field in new records) and the local mirror records `requirement=None` (its durable twin with the same event id is what the Requirement retrospective reads). `requirement_evidence` matches a record when its `work_identity` equals `parent_identity(requirement)`; legacy records that stored a `requirement` reference still match by that reference. Rejected: a workflow variable or a secret with Backlog read access (adds private configuration and credentials to the runner); recording the private reference or an opaque handle on the candidate at admission (needs a new record field, a backfill command for existing candidates and a second resolution path, and the handle scheme maps one handle per Issue/change, which `private_lineage` reserves for integration branches). `resolve_lineage` remains for the local-only post-merge obligations.
2. **Malformed attribution fails early.** Because attribution is pure, the only failure is a malformed managed branch; it raises `QueueError` naming the branch.
3. **Preflight before review.** `run_claimed` derives the attribution for the candidate branch after claim validation and before the `reviewing`/`repairing` transition and the reviewer/writer start. Failure raises `WorkerError` with the cause; the hosted outcome is red `refused-or-failed`; no head moves. Evidence posting failures (GitHub write) still fail the transition explicitly, as today.
4. **Own-push convergence.** A helper `await_pushed_head(pr_head, pushed, previous, timeout)` polls the PR head after a successful lease push: equal to `pushed` returns; a third sha raises `Discarded`; still `previous` after the bound raises `WorkerError("PR head did not converge to pushed head ...")`. Used by review, repair and finalize result paths before the `current_head` comparison. The lease push already proves nobody moved the branch before it; the wait only absorbs observation lag and never substitutes another strategy.
5. **Content-bound gate continuity.** In `candidate_lifecycle` validated-push recovery for `review`/`repair`, gates whose identity has the same task-content digest as the receipt identity are kept (rebound to the receipt identity), matching the existing integration-repair recovery. In `_transition`, when no exact-head record exists, gates of the latest record whose identity digest equals the final identity digest are carried even with `inherit_identity=False`, but only when the head was reached through a trusted harness push recorded for that latest record's head (validated-push receipt or v1 `update` with `worker_job`). Head-only legacy gates still never survive a head move.
6. **`restore-gates` recovery.** For a candidate in `finalize-pending`, `review-pending` or `blocked-retryable` whose current record lacks content-bound gates, the command walks trusted records/receipts backwards from the current head: every hop must be a trusted harness push (validated-push receipt or worker update) whose identity digest equals the current digest, until a trusted record that holds gates bound to that same digest. It then publishes one record on the current head with those gates merged under the current state and reason `restore content-bound gates`. Any break (foreign push, changed digest, missing or untrusted receipt) refuses with the named hop. No LLM run, no claim, no history rewrite; merge authority stays with the queue.

## Risks

- Bounded wait lengthens a job by at most the timeout (default 60 s) when the API lags.
- Local friction mirrors of coordinator events no longer carry the Requirement reference; Requirement retrospectives read the durable twin (same event id). When the durable source is unreadable and the gap is accepted, those local mirrors are matched by task branch only.
