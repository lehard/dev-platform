## Architecture
One self-contained portable `local_workspace.py` runtime is distributed with the platform. An operator-owned external JSON registry binds reviewed workspace roots and repository identities to local checkout policies. Installation copies the reviewed runtime into a shared machine-local runtime directory; sync updates it idempotently and attaches only identity-matched registered integration checkouts. Source roots are explicitly allowed; only files under allowed roots (including explicitly named root files) are checked with secret/cache exclusions and without symlink following.

Git attachment uses a local hooks dispatcher directory and retains an exact delegation to the original hooks directory. Doctor-managed pre-commit/pre-merge hooks remain in their normal directory and are dynamically delegated, so doctor refresh keeps working. Already-configured operator hooks remain delegated as well. Hook input/arguments and exit codes are preserved. A post-checkout action repairs only the current user's own new worktree administration and allowed source paths. It never touches a foreign active task.

A local Git config key points at the external policy. Updated shared_workspace preflight and intake consult it without widening their registered paths; the external launcher supplies before/after checks for older downstream scripts. Launcher sets umask 0002 and validates checkout/worktree ownership. The central-only foreign-worktree missing-setgid workaround stays narrowly scoped to the existing adapter; new policy does not bypass other permission defects.

Per-user LaunchAgent runs bounded fleet sync/audit periodically and at login. Current-user owned approved paths can be repaired; foreign-owner drift is diagnosed with path, owner and minimal action. A single account never claims repair for both users. Registry automation discovers only first-level reviewed workspace checkouts whose origin exactly matches approved project inventory; it never publishes source changes or changes active worktree contents. Removal restores original local hook config and removes only generated files.

## Risks and Mitigations
Permission widening: default exclusions plus explicit allowed source roots, no symlinks, owner-only mutation and reviewed group membership. Hook loss: dynamic delegation and executable/input/exit regression checks. Concurrent edits: use no-follow descriptors and stable identity checks; report failures without replacing files. Background interference: only metadata permission repair on integration source and current-user tasks; no content changes, Git reset or foreign-tree writes. Distribution drift: compare runtime digest, record installed identity and repeat install safely. Unsupported OS/user access: explicit diagnostics and no sudo. Arbitrary editor masks cannot be guaranteed prospectively; directory inheritance, bounded owner audit and lifecycle admission catch drift.

## Supervisor clarification before completion
Automatic updates use an explicitly reviewed source checkout, origin, branch and runtime path. Only a committed, unchanged runtime blob at that source is eligible; installed automation consumes that blob without manual recopying. Generated external shared runtime state is cooperative group-writable state with serialized atomic updates, distinct from owner-only source repairs. Discovery can restrict checkout names to omit recovery clones. Explicit `.agents/skills` source roots are allowed while other private agent state remains excluded. Existing central operator adapter remains composed and requires a compatible local migration before central attachment. Real installation follows successful independent review; publication and parent terminal reconciliation are lifecycle steps after implementation verification.

Direct repair, launcher and inherited hook execution enforce the same reviewed workspace-root boundary as discovery. External runtime and registry paths are rejected inside any project checkout before any generated-state mutation. All runtime publication occurs under the fleet lock; installed code reloads the committed update after that serialized publication. Shared hooks resolve `python3` through the invoking user's PATH rather than recording the first user's private interpreter. Per-user LaunchAgent retains its own installer interpreter. Removal preserves its plist and fails if a live LaunchAgent cannot unload. Source enumeration errors remain admission findings.
